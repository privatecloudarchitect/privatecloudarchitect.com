The availability floor: a gate, not a score
The strip beside this shows one row per member cluster and one column per check. Every cell is a yes or no verdict, and no cell ever earns points. The posture’s floor is its worst row. Only member clusters appear here. A cluster you expect but don’t see has no posture VMs reconciled onto it yet.
Uptime is table stakes
The floor asks one question: would a host failure be survivable? Five checks answer it. HA admission control must be enabled with the host-failures policy. The cluster needs N+1 redundancy: at least two member hosts and a failover level of at least 1. DRS must be fully automated, because DRS restores placement after the failover. Failover headroom must hold: consumed memory stays within 100% of HA-usable DRAM, so the load still fits after the failure. Effective-N must be intact: zero HA config issues, and hosts connected to the master must equal member hosts minus the master (N-1). Capacity, performance, and cost tuning only mean something above a satisfied floor.
Three states, one precedence
PASS The check is verified true on that cluster. Green means verified, never assumed.
BREACH Verified false. Admission control turned off on a member cluster is a real breach: this posture requires it. At this tier a floor breach pages. Restore the check before you read anything below.
UNVERIFIED The check cannot be verified from here. Instrument it or confirm it by hand. A floor you can’t observe hasn’t passed. Precedence: breach beats unverified, and unverified beats pass.
When the floor is red, the scores below are not meaningful. A perfectly tuned envelope on a cluster that can’t survive a host failure is a well-decorated outage. Restore the floor first. The floor never recolors or zeroes the scores. The strip and its alert carry the urgency. When every cell is green, the floor is holding. That is the state this page exists to protect.
