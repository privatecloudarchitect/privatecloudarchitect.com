The operating rhythm
A tuned private cloud is a habit, not a project. Each rhythm below ties to a specific signal on this scorecard moving in a specific direction.
Why a rhythm at all
An envelope only holds if someone checks it. Drift is quiet. A host gets packed past 1.1× during a busy week. A reservation gets dropped in a rebuild. A policy gets edited as a temporary fix and stays that way. The cadence catches each of these while the fix is still cheap. The daily pass catches active incidents. The weekly review catches slow erosion. The monthly true-up catches configuration drift.
Rhythm What you do Driven by (on this dashboard)
Daily Clear any red in the floor strip first. Nothing below it matters until the strip is green. Then act on the now clock: any VM swapping (always an incident at this posture) and any breach count above zero. Floor strip · VMs Swapping · VMs Over Ready / Contention Breach
Weekly The envelope review. Check which members entered the warn band on the window clock (the 95th-percentile columns). Work the worst VM, then the worst host. Run the reclaim actions the evidence view has already ranked. Skip any shrink the VM’s red peak vetoes. Contention view (p95 bands) · Host envelope view · Oversized-candidates drill-down
Monthly The true-up. Audit the policy against the posture catalog: an edited policy is drift even while the numbers look green. Confirm the anti-affinity rules on the replica pairs by hand (the one check this dashboard cannot see). Drive unpostured inventory toward zero. Ask whether any envelope value has earned a cited revision. Policy-parity check (pca) · floor-strip UNVERIFIED note · tag hygiene
Severity follows the tier. This is a production, latency-critical posture. A floor, performance, or capacity breach pages. A cost breach opens a ticket for the weekly review. The same envelope on a staging posture would ticket where this one pages. The response changes with the tier. The targets never do.
