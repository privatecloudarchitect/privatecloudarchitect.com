The floor: restartability
The strip beside this shows one row per member cluster. At best-effort the floor asks one question: if a host fails, does the work come back? Two cells carry the verdict; the rest is context.
What is judged
HA Restart Enabled must read on: this posture promises restart, nothing more (a string value, read it, it does not color). HA Config Issues must be zero, and turns red above zero: an HA cluster with a broken config keeps the one promise it makes only on paper. Those two cells are the floor. When restart reads off or config issues turn red, restore it before reading the scores below.
The rest is context, not a gate. Admission Control, HA Failover Level, Member Hosts, DRS Automation and Consumed % of HA DRAM are shown for orientation. This posture reserves no host-failure headroom, so admission control off and a failover level of zero are within posture, not breaches. An empty red set here is the designed state of a best-effort cluster, not a broken view.
A cluster you expect but do not see has no posture VMs reconciled onto it yet. Only clusters running this posture's workloads appear.
Floor definition: the Well-Tuned Private Cloud posture catalog, posture test-dev-traditional. Bounds are generator-stamped from the floor.
