Cost: density is the point
At best-effort the cost pillar leads, and it reads in two directions.
An under-packed cluster is a cost failure
Density Position leads the cost view. A cluster running well below its 2.0 overcommit target is paying for DRAM it does not use. That idle capacity is the same waste an over-packed prod-DB cluster represents on the performance side, read from the other end. Consolidate onto it before buying more.
Reclaimable is the other lever. Reclaimable Memory % scores VM-level oversize from the demand analysis, banded 20 / 35 / 50. The tolerance is wide because this posture already runs hot; only clearly oversized VMs move the score. Cost Coverage % is a validity gate: below the coverage threshold the dollar figures read as insufficient attribution, so a low number with low coverage is unknown, not green.
The move. Work the most under-packed cluster first: consolidate more workload onto it. Then shrink the clearly oversized VMs the reclaim evidence has ranked. A blank dollar is no cost attributed, not no opportunity; the GB ratio carries the score.
