The envelope & metric model
Every column on this scorecard, the signal it reads, and the envelope value that colors it. Nothing on this page is a house number. Every threshold comes from the posture catalog and is cited at the foot.

Column Signal Envelope (target / warn / breach)
Memory Overcommit (× DRAM) mem|guest_provisioned summed over member VMs ÷ mem:DRAM|memory_tier_total_capacity 1.0 / 1.1 / 1.25. The basis is DRAM. Tiering is withheld, so the strict ratio carries the band.

Worst Host Memory Overcommit max of the member hosts’ ratios 1.0 / 1.1 / 1.25. The cluster answers as its worst host.
Hosts Over Memory / CPU Envelope count of member hosts with envelope position > 1 Any > 0 is red. A now-clock column.
Consumed % of DRAM (host) 100 × mem|consumed_average ÷ mem:DRAM|memory_tier_total_capacity (Shared SM) Advisory ceiling 60 / 80 / 90. A saturation reading from the documented DRAM banding, not an envelope band.
Consumed % of HA DRAM (cluster) the floor’s failover-headroom signal, repeated in the capacity view Display gradient 85 / 95 / 100 toward the floor’s pass or fail ceiling of 100. Packing that eats the failover reserve is a deferred outage.
Context columns VM Memory Provisioned (GB) · VM vCPU Allocated · Member Hosts Unbanded: the raw quantities behind the ratios.
The position columns and heatmaps. An Envelope Position divides observed by breach, so 1.0 is the breach line for every signal. That is what lets the heatmaps hold fixed bounds: memory position 0 / 0.80 / 0.88 / 1.0, ready position 0 / 0.20 / 0.60 / 1.0. The interior stops are target÷breach and warn÷breach. The same color always means the same distance from the envelope. Cluster ratios divide summed numerators by summed denominators, never an average of per-host ratios. Skew hides in averages. That is why the worst-host column leads.
Performance (scored at the VM, 95th percentile over the 7-day window)
Column Signal Envelope (target / warn / breach)
CPU Ready % (p95) cpu|readyPct 1.0 / 3.0 / 5.0. Scheduling wait: the VM is paying now.
CPU Co-stop % (p95) cpu|costopPct 0.5 / 1.5 / 3.0. The wide-VM stall that Ready % understates.
Memory Contention % (p95) mem|host_contentionPct 0.0 / 0.5 / 1.0. Latency-weighted memory wait.
Memory Balloon % (p95) mem|balloonPct 0.0 / 0.5 / 2.0. Pressure building.
Memory Swapped (GB, current) mem|swapped_average 0. Any > 0 is a breach. This is a stock, the GB sitting in swap: presence is the event.
Reservation config|memoryAllocation|reservation (property) Required at this posture. A zero reservation is drift, not savings.
Limit config|memoryAllocation|limit (property) −1 (unlimited) is correct. Anything ≥ 0 is a configured limit that silently manufactures contention.
VMs Swapping · VMs Over Ready / Contention Breach count of member VMs past the breach bound Any > 0 is red. The now clock.
Context columns cpu|demandmhz · mem|active_average · mem|consumed_average Unbanded. High contention with high demand means grow or de-densify. High contention with low demand on a wide VM means fewer vCPUs.
Why p95, and where the fix lives. The scorecard judges contention at the peak. A daily mean smooths away the spikes the SLA feels. Balloon or swap on a VM is a symptom. Its root cause lives on the host. The durable fix is de-densify, rebalance, or reserve, not tuning the VM.
Cost (scored at the cluster)
Column Signal Envelope (target / warn / breach)
Reclaimable Memory % member reclaimable GB (oversize only, clamped at zero) ÷ provisioned GB, from the Shared per-VM reclaimable metric over mem|guest_provisioned 5 / 15 / 25. Headroom is priced in. Only unclaimed oversize moves it.
Reclaimable Envelope Position observed ÷ 25 0.20 / 0.60 / 1.0. The same ruler as every other position.
Cost Coverage % members carrying cost|effectiveProjectedTotalCost ÷ member VMs GATE. It caps the dollar read and is never scored. Red below the threshold the column carries.
Fleet Reclaimable Cost (USD/mo) the Shared fleet-reclaimable-cost metric Unbanded. The GB ratio carries the score. The dollar helps you make the case to finance.
Total Cost (USD/mo) cost|effectiveProjectedTotalCost summed over member VMs Unbanded. The projected monthly figure. It stays stable across the month, unlike a month-to-date total.
Cost per Workload (USD/mo) Total Cost ÷ Member VMs Baselined at activation. Reported, not banded. The trend is the finding.
The two clocks
Window clock The banded 95th-percentile columns over the 7-day window. It answers whether the SLA was protected this week. The weekly review reads this surface.
Now clock The count columns (VMs Swapping, hosts and VMs over breach) and the alerts behind them. It answers who is out right now. The daily pass reads this surface.
One envelope drives both clocks. The alerts substitute persistence for the percentile. A signal must hold its breach across consecutive collection cycles before it pages. A single spike triggers nothing. A sustained breach cannot hide.
