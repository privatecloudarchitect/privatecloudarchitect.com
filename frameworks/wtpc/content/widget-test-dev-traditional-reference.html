The envelope and metric model
Every band on this scorecard is generator-stamped from these values. The envelope is the single source; the views render it.
Signal target / warn / breach Reading
Memory Overcommit (x DRAM) 2.0 / 3.0 / 4.0 Density is the point. The band is the safety ceiling; past 4.0 is the thrash cliff.
CPU Overcommit (vCPU per pCPU) 4.0 / 6.0 / 8.0 High packing by design.
CPU Ready % (p95) 5 / 10 / 15 Loose. Perceived latency is not gated here.
Memory Contention % (p95) 1 / 3 / 5 Expected under density.
Reclaimable Memory % 20 / 35 / 50 Wide tolerance. Oversize is still waste, but the bar is generous.
The position ruler. An envelope position divides observed by breach, so 1.0 is the breach line on every signal. Density Position runs the other way: it divides the overcommit target by what is observed, so a value above 1.0 means the cluster sits below its target, the under-use the cost pillar exists to catch. Co-stop, Balloon and Swapped carry no envelope edge at this posture and are shown for context. Reservations are not expected; a best-effort VM holding one is a governance finding, surfaced on the estate governance dashboard.
Every value: the Well-Tuned Private Cloud posture catalog (docs/design/private-cloud-tuning-framework/), posture test-dev-traditional.
