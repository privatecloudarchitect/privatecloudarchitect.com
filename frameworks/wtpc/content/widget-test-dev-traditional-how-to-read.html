How to read this scorecard
This posture is best-effort: restartable work, packed densely and cheaply. Density is the goal. The scorecard reads gate first, then scores each pillar as distance from this posture's envelope.
SLA Best-effort. Restartable only. A breach is a ticket for the weekly review, not a page.
Design point Density. Overcommit runs 2:1 toward 4:1. Idle hardware is the failure to catch, not a safe state.
Members Everything tagged env=dev · sla=sla-4: the VMs. Their hosts and clusters follow, derived from where those VMs run.
Gate, then score
The floor is a pass or fail gate: restartability holds, or it does not. Nothing below the floor is meaningful until it is green. Then each pillar scores as a color, where green means within this posture's envelope, not a universal ideal. The same 2:1 overcommit that reads green here would breach a latency-critical posture. Each posture answers only to its own targets.
Under-density is the cost failure. The cluster and cost views lead with Density Position: a cluster running well below its overcommit target is capacity you bought and did not use. Over-packing past the safety breach is the other edge, the thrash cliff. Both are real; the pillar bands carry each.
Contention is expected here. CPU Ready and Memory Contention are scored against loose bands. Co-stop, Balloon and Swapped are shown for context and carry no envelope edge at this posture. Every view sorts worst-first, so the top row is the pillar.
