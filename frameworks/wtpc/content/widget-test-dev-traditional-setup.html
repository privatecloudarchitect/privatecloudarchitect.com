Setup (one-time)
Four steps bring this scorecard live. The super metrics import as definitions; activation is a console step.
1 · Object type Each super metric imports as a definition only. Set its Object Type from the name's object slot (Host System · Virtual Machine · Cluster Compute Resource) and its Unit from the name's suffix.
2 · Enable In PCA - WTPC - Policy - test-dev-traditional, enable the 32 posture super metrics, plus the 4 Shared and the 4 Rightsizing metrics the drill-down renders. Per-policy enablement is the scoping mechanism: members compute, everything else stays dark.
3 · Tags Membership is two tags (env=dev · sla=sla-4) on the VMs. Their hosts and clusters are derived from where those VMs run, so run the reconciler on a cadence to keep the infrastructure tiers current.
4 · Blanks A blank cell has three legitimate reasons: the object is not a posture member, the metric is not yet enabled in the policy, or the cost engine has not attributed a value yet. This posture ships no alert definitions; a breach is a dashboard color for the weekly review.
Activation reference: the Well-Tuned Private Cloud content authoring doctrine (docs/reference/vcf-ops/content-authoring/).
